# 02 PRD — 信貸撥貸金額預測工具

## 使用者、工作與情境

**主要使用者**：銀行信貸電話行銷人員。他們完成客戶 KYC 後，很難評估這位客戶大概能核准多少，因此無法決定要推哪種方案，也無法和主管談行銷細節（依據：brief §待解痛點）。

**次要使用者**：電銷主管。主管每天和業務討論名單，需要看到每位客戶的預測結果與判斷理由（依據：brief §成功指標）。

**模型維護者**：負責用新的撥貸資料重訓，並確認成績沒有因資料外洩而偏樂觀（依據：brief §主要約束）。

| ID | 目標 | 判斷方式 | 來源 |
|---|---|---|---|
| G-01 | KYC 後能立刻取得參考核准金額與等級 | 單筆輸入後 1 秒內顯示金額、低／中／高等級；保留集 MAE 優於「一律猜中位數」至少 15% | brief §期望成果 `[L]` |
| G-02 | 每日一次把名單的預測結果帶去和主管討論 | 上傳當日名單 CSV 後，可下載 `預測結果_YYYYMMDD.csv` | brief §成功指標 `[L]` |
| G-03 | 預測理由講得出來，主管能理解 | 決策樹頁面顯示 ≤4 步判斷路徑與同群組金額區間 | 由 G-02「與主管討論」推得 `[L]` |
| G-04 | 成績不因撥貸後資料而偏樂觀 | 評估報告同時列出移除「無擔保總餘額、DBR」後的成績 | brief §主要約束 |

**主流程（單筆）**：開啟 `撥貸金額預測工具.html` → 選四個類別屬性、填六個數值 → 按「預測」→ 看到預測金額、等級與「高於／不高於中位數」標籤；若輸入超出訓練範圍，另有黃色提示。

**主流程（每日批次）**：選擇當日名單 CSV → 畫面顯示筆數、等級分布與前 30 筆 → 按「下載預測結果 CSV」→ 把檔案附在與主管的討論中。

**失敗流程**：CSV 缺少必要欄位或沒有資料列時，顯示紅字錯誤，且不出現下載按鈕。使用者修正檔案後重新選擇即可。

**保存與重新進入**：工具不保存任何資料。結果只存在使用者下載的 CSV 裡；重新整理頁面後，表單會回到預設值。

## 故事與驗收條件

### US-01 單筆預測核准金額（G-01）

身為電銷人員，我想在 KYC 後輸入客戶條件，立即看到參考核准金額，以便決定推薦方案。

- AC-01.1：Given 行業屬性C、學歷／居住／婚姻未填、循環比 10、無擔保總餘額 20、DBR 12，其餘 0 When 按「範例／重設」 Then 顯示預測金額 14.8、等級「低」、標籤「不高於中位數 40」（以 2026-11-10 訓練的模型為準）。
- AC-01.2：Given 預測金額 a 與切點 (c0, c1)＝(28.96, 50.05) When 判定等級 Then a ≤ c0 為「低」、c0 < a ≤ c1 為「中」、a > c1 為「高」。邊界值 28.96 為「低」，50.05 為「中」。
- AC-01.3：Given DBR = 30 且無擔保總餘額 = −5 When 預測 Then 仍顯示金額，並提示「DBR 30 超出訓練範圍，已截斷至 21.98」與「無擔保總餘額為負值，已視為 0」。DBR = 0 視為「未提供」，不提示。

### US-02 用決策樹說明判斷理由（G-03）

身為電銷人員，我想看到這位客戶落在哪一群、為什麼，以便向主管說明。

- AC-02.1：Given 與 AC-01.1 相同的輸入 When 在 `撥貸金額(決策樹判斷).html` 按「範例／重設」 Then 顯示預測金額 30（群組中位數）、常見區間 20～40、群組筆數 29,850、標籤「偏低」，以及 4 步判斷路徑：行業屬性A 否 → 行業屬性E 否 → DBR ≤ 14.93 → 循環比 > 2.28。
- AC-02.2：Given 群組中位數 > 全體中位數 40 When 判斷 Then 標籤為「偏高」，否則為「偏低」。

### US-03 每日名單批次預測（G-02）

身為電銷人員，我想一次上傳當日名單，以便把整份預測結果帶去和主管討論。

- AC-03.1：Given 含 26 個特徵欄的 CSV（可另含「撥貸金額」或其他欄位） When 上傳 Then 顯示「已預測 N 筆」與低／中／高筆數。下載檔保留原有欄位與值，並在最後加上「預測撥貸金額、預測等級、預測高低」三欄，檔名為 `預測結果_YYYYMMDD.csv`（當天日期）。若含「撥貸金額」欄，另顯示 MAE。
- AC-03.2：Given 缺少「DBR」欄的 CSV When 上傳 Then 顯示「缺少欄位：DBR」，不出現下載按鈕，也不產生任何結果。
- AC-03.3：Given Big5 編碼的 CSV When 上傳 Then 中文欄名能正確辨識，結果與 UTF-8 版本相同。

### US-04 重訓並檢查成績（G-01、G-04）

身為模型維護者，我想用新資料重訓並得到可信的評估報告，以便判斷新模型能否上線。

- AC-04.1：Given `regression8.csv` When 執行 `python src/train.py` Then 產出 `reports/metrics.md`，內容包含保留集 MAE／R²、品質門檻結果，以及移除「無擔保總餘額、DBR、DBR_為0」後的成績。
- AC-04.2：Given 任何一項品質門檻未通過 When 執行訓練 Then 結束碼為 2，且 `dist/` 中的現有工具不被覆蓋。

## 產品規則與體驗

兩個工具都是單一 HTML 檔，可以離線開啟。客戶資料只在瀏覽器內計算，不會上傳。

| 情境／規則 | 使用者看見的結果與資料變化 | 來源／AC |
|---|---|---|
| 類別未選 | 該組視為「未知」，仍可預測 | 資料中有 4–8% 未填；AC-01.1 |
| 數值欄空白或非數字 | 視為 0 | AC-03.1 |
| 兩個工具金額不同 | 以預測工具（梯度提升）為主要參考數字；決策樹只用來說明理由與區間 | ADR-03；AC-01.1、AC-02.1 |
| 同一份檔案重複上傳 | 重新計算，結果相同；不累積任何資料 | AC-03.1 |
| 上傳失敗後修正 | 重新選擇檔案即可；先前的錯誤訊息與表格會清除 | AC-03.2 |

金額單位沿用原始資料，目前假設為「萬元」。這項前提待業務主管確認（期限：首次與主管討論前）。

## 範圍、依賴與待決

- **依賴**：撥貸歷史資料 `regression8.csv`，232,499 列，去重後 226,578 筆。

- **待決 D-02**：金額單位與電銷人員實際取得 DBR 的方式。決策人：業務主管。
