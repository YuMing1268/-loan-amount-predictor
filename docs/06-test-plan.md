## 範圍、風險與策略

最怕的失敗是：電銷人員看到的數字和訓練出來的模型不同（JS 推論錯誤），或模型成績因外洩而偏樂觀，導致主管據此下錯決策。自動化測試直接測 `dist/` 成品裡的 JS（用 Node 執行），並以 sklearn 重訓的模型作為獨立 oracle。畫面外觀與真實瀏覽器的檔案操作則由人工驗收。

- **JS 推論與模型不一致（高）**：數字錯了卻沒人發現。以 1,500 筆真實資料逐筆比對 JS 與 sklearn 的結果（TC-05、TC-06），另測決策樹門檻的等號邊界（TC-06b），因為真實資料剛好不會落在門檻上。
- **特徵規則兩邊不一致（高）**：例如類別未填、DBR 為 0、出現負值。用手算的決策表，同時測 Python 與 JS（TC-03）。
- **外洩造成成績偏樂觀（高，brief 主要約束）**：資料本身無法證明兩個欄位的取得時點。測試只能確保消融報告存在、數字合理（TC-07）；真正的判定要等 D-01 由人決定。
- **批次 CSV 錯誤（中）**：缺欄位、Big5 編碼、引號內含逗號。以 API-03 純函式測試（TC-09、TC-10）。
- **較差的模型覆蓋上線版（中）**：測試門檻未過時 `dist/` 不變（TC-08b）。
- **不測的範圍**：瀏覽器之間的 CSS 差異（屬人工 MT-01）；sklearn 本身的正確性；超大檔案（超過 10 萬筆）的瀏覽器記憶體用量（待量測，負責人待指派）。

## 環境、資料與判定方式

```bash
pip install pandas scikit-learn pytest      # 版本見表頭
python src/train.py                          # 產生 dist/、models/、reports/（約 8 秒）
python -m pytest tests -v --junitxml=reports/pytest.xml
```

- **資料**：`regression8.csv`（232,499 列，去重後 226,578 筆）。抽樣的 seed 固定為 7，訓練 seed 為 42。TC-08 只取前 4,000 列，在 `tmp_path` 中訓練，不影響正式成品。
- **Oracle**：TC-03 用規格手算的結果；TC-05、TC-06 用測試內重新訓練的 sklearn 模型，不讀匯出的 JSON；TC-09 的 MAE 由測試自行計算；TC-14 用 3 秒門檻（NFR-06）。
- **JS 執行方式**：`tests/js_harness.js` 取出 HTML 的 `<script>`，在 `vm` 中執行（沒有 `document` 時只載入純函式）。`tests/ui_smoke.js` 則以 DOM 替身執行整頁程式。

### TC-03｜特徵規則（FR-04、NFR-02）

選這一層的理由：規則是最容易兩邊寫得不一樣的接縫。輸入為 SRS 決策表的 4 列。

1. 用 `make_features(df, (1.13, 21.98))` 產生 31 欄。
2. 預期：結果與手算的非零欄位完全相同，其餘欄位為 0。
3. 以 `dist` 中的 `toFeat` 對相同的 4 列計算，結果須與 Python 逐欄相同，`M.cols` 也須等於 `MODEL_COLS`。

執行：`tests/test_features.py`。

### TC-05｜瀏覽器預測等於 sklearn（AC-01.1、FR-06）

1. 在測試內用全部乾淨資料，以 `HGB_PARAMS` 重新訓練 sklearn 模型。
2. 從乾淨資料抽 1,500 筆（seed 7），把原始欄位餵給 `dist` 預測工具的 `predict`。
3. 預期：逐筆絕對誤差的最大值 < 0.001。

### TC-06｜決策樹（AC-02.1、FR-08）

- a：1,500 筆的 JS 葉中位數，須與 sklearn `apply` 後算出的中位數逐筆相同；路徑長度在 1 到 4 之間；`hi` 等於「中位數 > 全體中位數」。
- b：根節點特徵值剛好等於門檻時走左，等於門檻加 1e-6 時走右。

### TC-07／TC-08｜模型品質與重訓

- TC-07：`reports/metrics.json` 中兩個門檻皆為 true，且 MAE 依序為 HGB < 樹 < 基準；消融移除的欄位正確，移除後的 MAE 大於全特徵的 MAE；`clean.rows_out` 等於 HTML 的 `M.n`。
- TC-08a：用 4,000 列資料訓練兩次，`hgb.json` 完全相同。
- TC-08b：把門檻改成 0.01 後執行，`gates` 為 false，報告存在，但不產生 `dist/`。

### TC-09～TC-14｜批次、編碼、提示、畫面、隱私、效能

- TC-09：只有表頭或空字串時回傳「檔案沒有資料列。」；缺 DBR 時回傳「缺少欄位：DBR」。3 筆含「撥貸金額」與「備註」（備註值為 `"含,逗號"`）的資料：輸出共 4 行，表頭最後三欄正確，原始引號保留，金額與等級等於 `predict` 的結果，MAE 與測試自行計算的值相同。
- TC-10：同一段中文 CSV 分別以 Big5 與 UTF-8 編碼後解碼，結果都等於原文。
- TC-11：DBR 30 加上無擔保 −5 時有兩則提示；DBR 0 與 12 時沒有提示；`outName(2026-01-05)` 回傳 `預測結果_20260105.csv`。
- TC-12：兩頁的畫面程式都能執行完成；表單有 10 個輸入；按「範例／重設」後，結果中有「預測撥貸金額」或「判斷路徑」；副標題顯示 226,578。
- TC-13：兩頁都不含 `fetch(`、`XMLHttpRequest`、`sendBeacon`、`WebSocket`、`<script src`、`<link `、`<img `。
- TC-14：取 `regression8.csv` 前 10,000 筆做批次預測，筆數為 10,000 且耗時 < 3,000 ms。
